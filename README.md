# memorybot

Telegram-бот, который раз в день присылает дайджест: что вы писали в свой блог ровно год,
два, три и больше лет назад.

- Каждый день в **12:00 по Москве** присылает дайджест: из каждого прошлого года — **одно**
  случайное сообщение за этот же день и месяц (год назад, два, три и так далее).
- Без собственных комментариев: только пересланные посты, никаких заголовков и подписей.
- **Молчит**, если в этот день ни в одном из прошлых лет ничего не было записано.
- Если в каком-то году записей за день несколько — выбирает **случайную**, но сначала из тех,
  которые ещё ни разу не присылал.
- Пересылает оригинал поста, а не пересказ: остаются медиа, форматирование и подпись канала.
  Альбом пересылается целиком, как одна запись.

## Как это работает

Bot API не даёт читать историю канала, поэтому архив набирается с двух сторон:

| Источник | Что попадает в архив |
| --- | --- |
| Бот-администратор канала | все новые и отредактированные посты, автоматически |
| Бот-администратор группы | новые сообщения: все, если группа указана в `BLOG_CHAT_ID`, иначе только ваши |
| Экспорт Telegram Desktop (`result.json`) | вся прошлая история — её и нужно поднять один раз |
| Пересланный боту пост | одна запись с исходной датой публикации |

Права администратора нужны в обоих случаях: обычным подписчиком бота в канал вообще не
добавить, а в группе Telegram скрывает от него сообщения, пока он не админ. Никаких
разрешений при этом выдавать не требуется — галочки можно снять все.

Записи хранятся в SQLite: id канала, id сообщения, дата, текст и тип вложения. Сами файлы
не копируются — в нужный день бот просто пересылает исходное сообщение.

## Быстрый старт

Нужен Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
git clone <этот-репозиторий> memorybot && cd memorybot
uv sync

cp .env.example .env
# впишите BOT_TOKEN от @BotFather
```

Проверить, что всё живо, можно без токена — на приложенном примере экспорта:

```bash
uv run memorybot import examples/blog_export_sample.json
uv run memorybot check          # что бот прислал бы сегодня
uv run memorybot stats
```

Запуск:

```bash
uv run memorybot run
```

Дальше — в Telegram:

1. Напишите боту `/start`. Первый, кто это сделал, становится владельцем; остальным бот
   не отвечает. Это обязательный шаг: пока вы не начали диалог, Telegram не даст боту
   писать вам в личку.
2. Добавьте бота администратором в канал или группу с блогом — новые записи он запомнит
   сам и сразу подтвердит в личке, что теперь их видит.
3. Поднимите архив: в Telegram Desktop откройте канал → «Экспорт истории» → формат **JSON**,
   без медиафайлов. Полученный `result.json` пришлите боту в личку или скормите на сервере:

```bash
uv run memorybot import /путь/к/result.json
```

## Настройки

Всё задаётся в `.env`; расписание и часовой пояс можно менять на ходу командами бота.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `BOT_TOKEN` | — | токен от [@BotFather](https://t.me/BotFather), обязателен |
| `OWNER_ID` | пусто | ваш Telegram id; если пусто — владельцем станет первый, кто напишет `/start` |
| `BLOG_CHAT_ID` | пусто | `-1001234567890` или `@myblog`; если пусто, бот индексирует все каналы, куда его добавили, а в группах — только ваши сообщения |
| `TIMEZONE` | `Europe/Moscow` | по какому времени определяется «этот день» |
| `DIGEST_WINDOW` | `12:00` | время дайджеста; одно значение (`12:00`) — строго это время, диапазон (`10:00-20:00`) — случайный момент внутри него |
| `MIN_YEARS_AGO` | `1` | насколько старой должна быть запись |
| `DB_PATH` | `data/memorybot.sqlite3` | файл архива |
| `TELEGRAM_API_BASE` | пусто | свой сервер Bot API; нужен, только чтобы присылать боту экспорт больше 20 МБ |

Момент внутри окна выбирается случайно, но **детерминированно для конкретного дня**:
перезапуск бота днём не сдвинет уже назначенное время и не приведёт к второму напоминанию.
Если бот был выключен в назначенную минуту, он догонит расписание, пока окно ещё открыто.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/today` | проверить сегодняшний день прямо сейчас |
| `/on 5.09` | все воспоминания за 5 сентября из прошлых лет |
| `/on 2019-09-05` | записи ровно за эту дату |
| `/random` | случайная запись из архива |
| `/stats` | сколько записей, за какие годы, из каких каналов |
| `/settings` | текущее расписание, пояс и время следующей проверки |
| `/window 09:00-13:00` | сменить окно напоминаний |
| `/timezone Europe/Berlin` | сменить часовой пояс (даты записей пересчитываются) |
| `/pause`, `/resume` | временно выключить и включить напоминания |

## Команды в терминале

```bash
memorybot run                              # запустить бота
memorybot import result.json [--chat-id N] # загрузить историю из экспорта
memorybot check [--date 2026-09-02]        # что было бы отправлено в этот день
memorybot stats                            # содержимое архива
```

`--chat-id` нужен, если в экспорте нет id канала или вы хотите привязать историю
к конкретному чату в формате Bot API (`-1001234567890`).

## Как бот доставляет запись

По очереди, пока не получится:

1. `forwardMessage` — оригинал со ссылкой на канал (для альбома — `forwardMessages`);
2. `copyMessage` — копия без подписи, если пересылка запрещена настройками канала;
3. текст записи со ссылкой на пост — если сообщение недоступно совсем
   (например, история поднята из экспорта, а бота в канале нет).

## Запуск на своём VDS

Подойдёт любой Debian или Ubuntu с systemd, самой дешёвой конфигурации хватает с запасом.
Бот работает через long polling, поэтому ни домена, ни открытых портов, ни сертификатов
не нужно — достаточно исходящего доступа к `api.telegram.org`.

### 1. Забрать код на сервер

Репозиторий приватный, поэтому либо авторизуйтесь на сервере:

```bash
curl -fsSL https://downloads.cursor.com/origin/install.sh | sh
origin auth login
origin repo clone divoannet/blog-rewind
cd blog-rewind
```

либо скопируйте рабочую копию со своей машины, не авторизуясь на сервере:

```bash
rsync -a --exclude .venv --exclude data --exclude .env blog-rewind/ vds:~/blog-rewind/
```

### 2. Установить

```bash
sudo deploy/install.sh
```

Скрипт создаёт системного пользователя `memorybot`, копирует проект в `/opt/memorybot`,
собирает виртуальное окружение (при необходимости сам поставит `uv`), готовит `data/`
для архива, кладёт `.env` с правами `640` и включает сервис в автозапуск. Запускать его
можно повторно — это же и способ обновиться.

### 3. Вписать токен и запустить

```bash
sudoedit /opt/memorybot/.env      # BOT_TOKEN=...
sudo systemctl start memorybot
journalctl -u memorybot -f
```

В логе должно появиться `Запускаюсь как @вашбот`. Дальше — `/start` боту в личку.

### Бот и ваша SSH-сессия

Сервис systemd запускается не из вашей сессии, а от `init`, поэтому выход по SSH ему
безразличен — можно закрывать терминал сразу после `systemctl start`. Убедиться,
что всё именно так:

```bash
systemctl is-active memorybot    # active
systemctl is-enabled memorybot   # enabled — значит поднимется и после перезагрузки
systemctl show -p MainPID memorybot
```

`is-enabled: enabled` означает автозапуск при загрузке сервера, `Restart=always` в юните —
что бот вернётся и после неожиданного падения или обрыва сети.

А вот запуск руками, вида `uv run memorybot run` или `memorybot run` прямо в терминале,
к сессии как раз привязан: при выходе процесс получит `SIGHUP` и умрёт. Так удобно
посмотреть на логи вживую, но для постоянной работы нужен именно сервис. Если хочется
подержать бота в интерактивном режиме и всё-таки отключиться — заверните его в `tmux`:

```bash
tmux new -s memorybot        # внутри: memorybot run
# отключиться, не убивая: Ctrl+B, затем D
tmux attach -t memorybot     # вернуться
```

Ещё одна тонкость на будущее: пользовательские юниты (`systemctl --user`) по умолчанию
останавливаются при вашем выходе из системы — для них нужен `loginctl enable-linger`.
Юнит из `deploy/` системный, так что это не про него.

### 4. Поднять архив прошлых лет

```bash
scp result.json vds:/tmp/
sudo -u memorybot /opt/memorybot/.venv/bin/memorybot import /tmp/result.json
```

Файл должен быть доступен на чтение пользователю `memorybot` — `/tmp` для этого годится.
Команды `import`, `stats` и `check` можно запускать из любого каталога: настройки и архив
бот находит по `.env` рядом с собой, а не по текущей папке.

### Обновление

```bash
cd ~/blog-rewind && git pull && sudo deploy/install.sh
```

`.env` и `data/` при этом не трогаются, а работающий сервис перезапускается сам.

### Бэкап

Архив — один файл SQLite. На ходу его правильно снимать средствами самой SQLite,
иначе можно получить копию без хвоста журнала WAL:

```bash
sudo -u memorybot sqlite3 /opt/memorybot/data/memorybot.sqlite3 \
  ".backup /tmp/memorybot-$(date +%F).sqlite3"
```

### Если что-то не так

```bash
systemctl status memorybot
journalctl -u memorybot -n 50 --no-pager
```

| Что в логе | Что это значит |
| --- | --- |
| `Не задан BOT_TOKEN` | пустой `BOT_TOKEN` в `/opt/memorybot/.env` |
| `Telegram не принял токен` | токен неверный или отозван; сервис не перезапускается по кругу — юнит останавливается на коде выхода 2 |
| `Telegram недоступен` | нет сети или закрыт исходящий доступ; systemd повторит попытку через 10 секунд |
| `Владелец не задан` | никто ещё не написал боту `/start` |
| тишина в нужный час | загляните в `/settings`: возможно, стоит пауза или архив пуст |

Сервис работает под непривилегированным пользователем и с включённой изоляцией systemd:
писать он может только в `/opt/memorybot/data`, всё остальное для него read-only.

## Разработка

```bash
uv run pytest        # тесты
uv run ruff check .  # линтер
uv run ruff format . # форматирование
```

Что где лежит:

| Файл | Ответственность |
| --- | --- |
| `anniversaries.py` | поиск годовщин и выбор случайной записи дня |
| `scheduler.py` | когда именно будить бота |
| `storage.py` | SQLite: архив, журнал отправок, настройки |
| `importer.py` | разбор `result.json` из Telegram Desktop |
| `indexer.py` | превращение сообщений Telegram в записи архива |
| `delivery.py` | пересылка с запасными вариантами |
| `handlers.py` | команды и роутеры aiogram |
| `service.py` | связывает всё вместе |
| `deploy/` | systemd-юнит и скрипт установки на сервер |

## Мелочи, о которых стоит знать

- 29 февраля вспоминается 28-го в невисокосные годы — иначе такие записи выпадали бы
  из ленты три года из четырёх.
- Альбом считается одной записью: и при выборе случайной, и при пересылке.
- Смена часового пояса пересчитывает локальные даты всех записей — граница суток
  сдвигается вместе с поясом.
- Бот отвечает только владельцу; ручной `/today` отменяет автоматическое напоминание
  в этот день, чтобы одно и то же не пришло дважды.
